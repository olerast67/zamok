# Zamok: дорожная карта

Все шаги от пустого репозитория до публичной версии 1.0, без сроков. Этапы идут по порядку: следующий начинается, когда закрыт предыдущий, кроме скорости (этап 9), которая идёт параллельно с этапа 3. На GitHub каждому этапу соответствует веха (milestone).

Как устроена программа: [docs/DESIGN.md](docs/DESIGN.md). Из чего собирается: [docs/STACK.md](docs/STACK.md).

## Этап 1. Прототипы

Отвечаем на все пометки **[проверить]** из DESIGN.md. Код прототипов лежит в `prototypes/` и в программу не переносится. По итогам каждого прототипа короткий отчёт в `prototypes/<номер>/REPORT.md` и правка DESIGN.md.

**P1. Подключение на путь папки**
- [ ] Файловая система WinFsp без шифрования, которая отражает обычную папку (passthrough)
- [ ] Подключение на путь `C:\...\Тест` от обычного пользователя, без прав администратора
- [ ] Проводник: открыть, создать, переименовать, удалить, перетащить, «Открыть расположение файла», открыть из VS Code и Word
- [ ] Иконка замка через `desktop.ini` в корне подключённой папки
- [ ] Видна ли папка другому пользователю этого компьютера
- [ ] Windows 11 в виртуальной машине, Memory Integrity включена
- [ ] Выбор: крейт `winfsp` или своя обёртка над `winfsp-sys`

**P2. Двойной клик по запертой папке**
- [ ] Способ A: `IContextMenu` делает «Открыть с паролем» действием по умолчанию только у запертых папок
- [ ] Проверить A в окне Проводника, в дереве слева, на рабочем столе, в диалогах открытия файла
- [ ] Перевести то же окно Проводника внутрь папки после пароля
- [ ] Способ B: Process Monitor, чем вход в папку отличается от подглядывания за миниатюрой и от индексатора
- [ ] Вывод: какой способ берём; элемент «Открыть с паролем» внутри папки остаётся запасным в любом случае

**P3. Запирание без отключения**
- [ ] Переключение состояния при открытом окне Проводника на этой папке
- [ ] Ярлык внутри папки, файл открыт в Word, папка открыта в VS Code
- [ ] Список процессов, которые держат файлы, из самой файловой системы
- [ ] Уведомление Проводнику, чтобы окно обновилось после запирания

**P4. Сбои**
- [ ] Убить процесс при подключённой папке: что видно в Проводнике
- [ ] Выключить виртуальную машину без завершения работы, загрузить снова
- [ ] Найти и снять «мёртвую» точку подключения при старте, подключить заново
- [ ] Перемещение запертой папки в Проводнике: что происходит с точкой подключения

**P5. Скорость без шифрования**
- [ ] Набор замеров: распаковка дерева на 70 000 файлов, `git clone`, `git status`, `npm install`, копирование 1 ГБ, открытие папки на 10 000 файлов
- [ ] Сравнение: NTFS против WinFsp passthrough
- [ ] Влияние `FileInfoTimeout` и многопоточности
- [ ] Реальные цели скорости для версии 1.0

**P6. Облака**
- [ ] OneDrive, Dropbox, Яндекс.Диск: открытая подключённая папка внутри синхронизируемой папки
- [ ] Уходит ли в облако расшифрованное содержимое через точку подключения
- [ ] Как облако синхронизирует скрытое хранилище `.Имя.zamok`
- [ ] Решение: разрешаем ли шифровать папки внутри облаков и с какими оговорками

**Итог этапа**
- [ ] DESIGN.md исправлен по всем отчётам, пометок **[проверить]** с риском для устройства программы не осталось
