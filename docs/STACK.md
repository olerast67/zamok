# Zamok: стек и устройство репозитория

Решение от 2026-11-07: ядро на Rust, окна на C# WinUI 3. Почему именно так, написано в [DESIGN.md](DESIGN.md), раздел 3.3. Здесь перечислено, из чего собирается программа и что нужно поставить на компьютер, чтобы её собрать.

Точные версии библиотек фиксируются в `Cargo.lock` и в файлах проектов C# при первом коммите кода, а не в этом документе.

## 1. Части программы и языки

| Часть | Язык | Во что собирается |
|---|---|---|
| `zamok-crypto` | Rust | библиотека: формат Cryptomator 8, шифрование имён и содержимого, ключ восстановления |
| `zamok-fs` | Rust | библиотека: файловая система WinFsp с двумя состояниями, кэши |
| `zamok-ipc` | Rust | библиотека: сообщения между частями программы, общая память со списком запертых папок |
| `zamok-core` | Rust | `zamok-core.exe`, фоновый процесс пользователя, значок в трее |
| `zamok-shell` | Rust | `zamok-shell.dll`, меню правой кнопки и двойной клик в Проводнике |
| `zamok-recover` | Rust | `zamok-recover.exe`, консольная расшифровка без установки и без WinFsp |
| `Zamok.UI` | C# | `Zamok.exe`, окна: пароль, мастер шифрования, ключ восстановления, настройки |
| установщик | WiX | `Zamok-<версия>.msi` с вложенным установщиком WinFsp |

Окна и ядро общаются через именованный канал Windows сообщениями в JSON. Прямого вызова кода Rust из C# нет: если окно упадёт, ядро и открытые папки продолжат работать, а ключи никогда не попадают в процесс окна, кроме момента ввода пароля.

## 2. Rust

- Компилятор: стабильный Rust через `rustup`, цель `x86_64-pc-windows-msvc`. Позже `aarch64-pc-windows-msvc` для ноутбуков на ARM.
- Windows API: крейт `windows` от Microsoft. Он даёт доступ к COM (для меню Проводника), к именованным каналам, к уведомлениям о блокировке экрана и сне, к Windows Hello.
- WinFsp: крейт `winfsp` (обёртка над C API WinFsp) или своя тонкая обёртка над `winfsp-sys`. Выбираем в прототипе P1 по тому, насколько обёртка полная и живая.
- Криптография, только проверенные библиотеки RustCrypto: `aes-gcm` (содержимое), `aes-siv` (имена), `aes-kw` (обёртка мастер-ключа), `scrypt` (ключ из пароля), `hmac` и `sha2`, `rand_core` и `getrandom` (случайные числа от системы), `zeroize` (стирание ключей в памяти). Для сверки копий при шифровании на месте `blake3`.
- Основу формата можно взять из `cryptomator-rs-crypto`, если её код окажется качественным. Решаем на этапе 2 после чтения кода.
- Остальное: `serde` и `serde_json` (настройки, журнал, сообщения), `thiserror` (ошибки), `tracing` (журнал работы программы без имён файлов и путей, чтобы журнал не стал утечкой), `tokio` для именованного канала.
- Проверки: `cargo fmt`, `cargo clippy` без предупреждений, `cargo test`, `proptest` (тесты на случайных данных), проверка разбора воспроизводимой мутацией байтов (`tests/fuzz_*.rs`, без nightly: `cargo-fuzz` на stable для Windows MSVC не запускается), `cargo deny` (лицензии и известные уязвимости в зависимостях).

## 3. C# и окна

- .NET 10, текущая версия с долгой поддержкой.
- Windows App SDK с WinUI 3, приложение без пакета MSIX (unpackaged) и со встроенной средой .NET (self-contained), чтобы человеку не нужно было ставить .NET отдельно.
- `CommunityToolkit.Mvvm` для связи окон с данными.
- Локализация: файлы ресурсов `.resw`, русский и английский с первого дня. Язык берётся из настроек Windows и меняется в настройках программы.
- Минимальная система: Windows 10 версии 1809, на ней работает WinUI 3. На Windows 10 окна без фона Mica.

## 4. Установщик, подпись, обновления

- WiX Toolset: собирает MSI, кладёт внутрь неизменённый установщик WinFsp, регистрирует DLL для Проводника, добавляет `zamok-core` в автозапуск пользователя.
- Права администратора нужны только при установке, для драйвера WinFsp и регистрации меню.
- Подпись: SignPath Foundation, когда проект станет публичным. До этого сборки без подписи, только для себя и тестеров.
- Обновления: окно настроек проверяет новый выпуск на GitHub только по кнопке (`HttpClient` из .NET, без дополнительных библиотек). Скачивание MSI со сверкой подписи будет, когда появится подпись; не обновляется, пока открыта хоть одна папка.
- Позже публикация в `winget`, чтобы ставить командой `winget install Zamok`.

## 5. Сборка и проверки на GitHub

GitHub Actions на `windows-latest`:
- на каждый коммит и запрос на слияние: форматирование, clippy, тесты Rust, сборка C#, `cargo deny`;
- на тег `v*`: сборка релиза, отпечатки SHA-256 всех файлов в описании релиза, черновик релиза на GitHub;
- по расписанию: fuzzing на ограниченное время, замеры скорости (раздел 7 DESIGN.md) с сохранением результатов, чтобы видеть, что стало медленнее.

Сборка воспроизводимая: из одного тега у любого человека получаются те же байты. Детали (фиксированные пути, время сборки) настраиваем перед первым публичным релизом.

## 6. Что поставить на компьютер для разработки

| Что | Зачем |
|---|---|
| Visual Studio 2022 Build Tools или Visual Studio Community: «Разработка классических приложений на C++» и Windows SDK | компоновщик MSVC для Rust и заголовки Windows |
| `rustup` со стабильным Rust | ядро |
| .NET 10 SDK | окна (у тебя .NET уже стоит, версию проверим) |
| WinFsp с компонентом Developer | драйвер и файлы для сборки |
| Git, GitHub CLI | уже стоят |
| Hyper-V и виртуальная машина с Windows 11 | проверка на Windows 11, на чистой системе, с Memory Integrity и Smart App Control |
| Sysinternals Process Monitor и Handle | смотреть, что делает Проводник при двойном клике и кто держит файлы |
| Cryptomator | создавать эталонные хранилища для тестов и проверять совместимость |

Разработка идёт на `C:\dev\zamok`: точку подключения на путь папки WinFsp ставит только на NTFS, а диск F: отформатирован в exFAT.

## 8. Правила работы в репозитории

- Основная ветка `main`, работа в ветках `p1-mount`, `crypto-format` и так далее, слияние через запрос на слияние, чтобы проверки GitHub Actions проходили до слияния.
- Сообщения коммитов по-английски, коротко, в повелительном наклонении: `Add scrypt key derivation`.
- Документация по-русски. Английский README и английский интерфейс появятся перед публикацией.
- Секретов в репозитории нет никаких. Тестовые хранилища создаются с тестовыми паролями, которые записаны рядом с ними.
