# Zamok: проект приложения

Документ описывает, как устроено приложение, как выглядит каждая функция и за счёт чего оно не теряет данные. Основа: три исследования в `docs/research/` (01 Проводник и монтирование, 02 формат и скорость, 03 жалобы пользователей). Пометка **[проверить]** значит, что решение держится на предположении, которое подтвердит или опровергнет прототип (раздел 10).

Название проекта Zamok («замок» латиницей). Стек описан в [STACK.md](STACK.md), шаги работы в [ROADMAP.md](../ROADMAP.md).

## 1. Для кого и зачем

Для человека, у которого на Windows 10 или 11 есть рабочие папки с документами, проектами и фотографиями, и он хочет, чтобы при краже ноутбука, копировании папки или чужом входе в его учётную запись эти файлы нельзя было прочитать.

VeraCrypt для этого неудобен: нужно выбрать файл тома, букву диска, ввести пароль, а файлы живут на отдельном диске, не там, где привык. Cryptomator требует создать хранилище и перенести в него файлы, а запереть его часто мешают открытые окна Проводника.

Наш принцип: **человек работает с папкой, а не с хранилищем**. Папка остаётся на своём месте, по своему пути, с теми же ярлыками и проектами в программах. Меняется только то, что без пароля она не открывается.

## 2. Что пользователь видит

### 2.1 Зашифровать

1. Правый клик по папке, «Зашифровать паролем».
2. Маленькое окно: пароль, повтор, полоса надёжности. Флажок «Открывать отпечатком или PIN-кодом Windows Hello», если Hello настроен.
3. Экран ключа восстановления: набор слов, кнопки «Сохранить в файл» и «Распечатать». Дальше нельзя, пока человек не введёт 4 слова из ключа по запросу. Так ключ точно где-то записан.
4. Прогресс с оставшимся временем. Отмена безопасна на любом шаге.
5. В конце папка на том же месте, открыта, иконка с открытым замком. Работа не прерывается.

Перед стартом программа проверяет и говорит человеческим языком, если что-то не так:
- диск NTFS (на флешках с exFAT и FAT32 не работаем, для них остаётся VeraCrypt);
- свободного места хватает на вторую копию папки плюс 10%;
- в папке нет файлов, открытых другими программами (список программ через Restart Manager);
- папка не системная (`C:\Windows`, `Program Files`, корень профиля) и не корень диска;
- в папке OneDrive нет файлов «только в облаке» (их сначала надо скачать).

### 2.2 Открыть

Двойной клик по запертой папке. Над окном Проводника появляется небольшое окно:
- иконка папки с замком и её имя крупно;
- поле пароля в фокусе, сразу можно печатать;
- если включён Windows Hello, запрос отпечатка или PIN-кода появляется сам, пароль остаётся запасным путём;
- Enter, окно закрывается, Проводник сразу показывает содержимое в этом же окне.

Неверный пароль: поле коротко вздрагивает, текст «Пароль не подошёл». Проверка пароля сама по себе занимает около секунды (так устроен scrypt), поэтому перебирать пароли медленно.

Как именно ловится двойной клик, описано в разделе 4. Запасной путь есть всегда: внутри запертой папки лежит один элемент «Открыть с паролем», а в меню правой кнопки есть пункт «Открыть».

### 2.3 Запереть

Папка запирается сама:
- при блокировке экрана (Win+L), по умолчанию включено;
- перед сном и гибернацией, всегда;
- при выходе из учётной записи и выключении, всегда;
- после N минут, когда в папке никто ничего не читал и не писал, по умолчанию 30 минут, настраивается для каждой папки отдельно.

Вручную: пункт «Запереть» в меню правой кнопки, «Запереть всё» в трее, сочетание клавиш (по умолчанию Ctrl+Win+L, можно поменять).

Если в момент запирания файлы из папки открыты в программах, человек видит уведомление: «Word держит Отчёт.docx. Запру через 60 секунд». Кнопки: «Запереть сейчас», «Отложить на 15 минут». Программа точно знает, какой процесс какой файл держит, потому что все обращения к файлам идут через неё (раздел 3.2). Перед сном ждать нельзя, там папка запирается сразу.

### 2.4 Остальное в меню правой кнопки

На зашифрованной папке: «Открыть» или «Запереть», «Сменить пароль», «Показать ключ восстановления» (после ввода пароля), «Расшифровать навсегда», «Свойства шифрования».

На обычной папке один пункт «Зашифровать паролем». Меню не захламляем.

### 2.5 Трей и окно настроек

Значок в трее: замок, закрашенный, если хотя бы одна папка открыта. Клик показывает список папок с состоянием и кнопку «Запереть всё».

Окно настроек:
- список зашифрованных папок: путь, размер, состояние, когда открывалась, время автозапирания для каждой;
- общие: запирать при блокировке экрана, Windows Hello, сочетание клавиш, язык (русский, английский);
- «Проверка следов» (раздел 6);
- «О программе»: версия, лицензия, строка про WinFsp (её требует лицензия WinFsp).

### 2.6 Внешний вид

- Интерфейс WinUI 3, как у приложений самой Windows 11: фон Mica, шрифт Segoe UI Variable, системный цвет акцента, светлая и тёмная тема по настройке системы. На Windows 10 те же окна без Mica.
- Окон мало и они маленькие. Главное окно приложения не нужно для работы: всё делается из Проводника.
- Своя иконка папки с замком в двух состояниях (заперта и открыта), во всех размерах от 16 до 256 пикселей, в стиле значков Windows 11.
- Без рекламы, без окон «купи Pro», без телеметрии.
- В интерфейсе нет слов «хранилище», «том», «монтирование». Есть «папка», «зашифровать», «открыть», «запереть».

## 3. Как это устроено

### 3.1 Главная идея: папка становится отдельным «диском без буквы»

После шифрования по пути папки (например `D:\Работа\Клиенты`) стоит не обычная папка, а точка подключения виртуальной файловой системы WinFsp. WinFsp это бесплатный драйвер, который позволяет программе показывать Windows папки и файлы, которых физически на диске в таком виде нет. Так работает Cryptomator.

Сами данные в зашифрованном виде лежат рядом, в скрытой папке `D:\Работа\.Клиенты.zamok`. Когда Проводник или Word просит файл, WinFsp спрашивает нашу программу, та читает зашифрованный кусок, расшифровывает его в памяти и отдаёт. Открытый текст на диск не пишется.

Почему скрытая папка рядом, а не где-то в одном месте:
- данные остаются на том же диске, переименование при шифровании мгновенное и атомарное (раздел 5);
- если папка лежит в Dropbox или Яндекс.Диске, в облако уезжает зашифрованная копия;
- чтобы перенести папку на другой компьютер, достаточно скопировать скрытую папку.

### 3.2 Папка подключена всегда, меняется только её состояние

WinFsp может подключить файловую систему только на путь, которого не существует (исследование 01, п. 1.1). Если бы мы подключали её при открытии и отключали при запирании, пришлось бы каждый раз удалять и создавать папку на этом пути, а открытое окно Проводника или ярлык не давали бы отключиться. Именно на это жалуются пользователи Cryptomator (исследование 03, п. 2.1).

Поэтому файловая система подключается при входе в Windows и висит постоянно. У неё два состояния:
- **заперта**: ключ стёрт из памяти, внутри виден только элемент «Открыть с паролем» и служебный `desktop.ini` для иконки. Иконка из `desktop.ini` в корне подключённой папки работает, если на точке подключения стоит атрибут «системный» (проверено в P1);
- **открыта**: видно расшифрованное содержимое.

Запирание это переключение состояния внутри нашей программы (проверено в P3, [отчёт](../prototypes/p3/REPORT.md)). Ядро WinFsp кэширует сведения о файлах и листинги каталогов, поэтому запирание обязано сбросить этот кэш через `FspFileSystemNotify`, иначе имена и размеры открытых файлов видны ещё до `FileInfoTimeout`. Атрибут «системный» для иконки Zamok ставит на точку подключения после каждого подключения: WinFsp создаёт её заново. Отключать ничего не надо, поэтому окно Проводника, открытое на этой папке, не мешает: оно просто обновляется и показывает запертый вид. Файлы, которые программы держали открытыми, при следующем чтении получают ошибку доступа. Поэтому перед запиранием и есть предупреждение из п. 2.3.

### 3.3 Из чего состоит программа

| Часть | Язык | Что делает |
|---|---|---|
| `zamok-core` | Rust | Фоновый процесс пользователя. Держит файловые системы всех папок, шифрование, состояния, таймеры автозапирания, слушает блокировку экрана и сон. Принимает команды по именованному каналу, доступному только этому пользователю. Рисует значок в трее. |
| `zamok-ui` | C#, WinUI 3 | Окна: пароль, мастер шифрования, ключ восстановления, настройки. Запускается по требованию и закрывается после. |
| `zamok-shell.dll` | Rust | Пункты меню правой кнопки и перехват двойного клика (раздел 4). Работает внутри Проводника, поэтому крошечный: не читает диск и сеть, состояние папок берёт из общей памяти, которую публикует core, команды отправляет core и сразу возвращается. |
| `zamok-recover` | Rust | Отдельная консольная программа без WinFsp и без установки: по паролю или ключу восстановления выгружает расшифрованную копию папки. Страховка на случай, если основная программа сломается или исчезнет. |
| установщик | WiX (MSI) | Ставит программу и неизменённый установщик WinFsp. Права администратора нужны один раз, для драйвера. |

Почему Rust для ядра: язык не даёт допустить целый класс ошибок работы с памятью, которые в шифровальщике превращаются в уязвимости, и позволяет надёжно стирать ключи из памяти после запирания (крейт `zeroize`, `VirtualLock`). В C# сборщик мусора может оставить копии ключа в памяти.

Почему C# и WinUI 3 для окон: это родной инструмент Microsoft для интерфейса в стиле Windows 11. У Rust нет зрелой библиотеки с таким видом.

Почему core это процесс пользователя, а не служба Windows от имени SYSTEM: ключи живут в процессе того, кто их ввёл, а файловая система отдаёт файлы только владельцу (дескриптор безопасности тома). Другой пользователь этого компьютера папку не откроет, даже когда она открыта у хозяина. Проверено в P1: WinFsp подключает том на путь папки от обычного пользователя ([отчёт](../prototypes/p1/REPORT.md)).

### 3.4 Формат хранения

Формат Cryptomator vault format 8 (исследование 02, п. 1):
- пароль превращается в ключ через scrypt, мастер-ключ хранится в файле `masterkey.cryptomator` в обёртке AES-KW;
- имена файлов шифруются AES-SIV, содержимое AES-GCM кусками по 32 КБ;
- структура папок скрыта: все папки лежат плоско в `d/XX/...`.

Почему не свой формат: если наша программа умрёт, человек откроет папку в Cryptomator на Windows, macOS, Linux, iOS или Android. Формат публичный и уже проверялся. Свою криптографию не пишем: AES, scrypt и прочее берём из библиотек RustCrypto.

Ключ восстановления это сам мастер-ключ, записанный словами. **[проверить]**, что наша запись совпадает с ключом восстановления Cryptomator, тогда его ключ подойдёт и к нашим папкам.

Что формат не прячет (пишем в README): сколько в папке файлов и подпапок, примерные размеры файлов, примерную длину имён.

В коде формат спрятан за интерфейсом `VaultFormat`, чтобы позже можно было добавить второй, быстрый формат для папок с тысячами мелких файлов (раздел 7).

### 3.5 Вход по Windows Hello

После ввода пароля мастер-ключ можно дополнительно обернуть ключом, который хранится в TPM (чипе безопасности компьютера) и выдаётся только после отпечатка, лица или PIN-кода Windows Hello. Обёрнутый ключ лежит в `%LOCALAPPDATA%\Zamok`.

Компромисс, который надо показать человеку при включении: кто знает PIN-код от Windows, тот откроет и папку. Ключ привязан к этому компьютеру, поэтому пароль и ключ восстановления остаются главными.

**[проверить]** конкретный способ: `KeyCredentialManager` (запрос Hello на каждое открытие, ключ из детерминированной подписи) или DPAPI с подтверждением через `UserConsentVerifier`. Подсмотреть у Cryptomator 1.17 (`cryptomator/integrations-win`).

## 4. Двойной клик по запертой папке

Самое рискованное место проекта. Варианты из исследования 01, п. 2, плюс один свой:

| Способ | Тот же путь | Риск уронить Проводник | Вердикт |
|---|---|---|---|
| A. Меню правой кнопки (`IContextMenu`) делает «Открыть с паролем» действием по умолчанию, но только у запертых папок | да | низкий, если обработчик крошечный | пробуем первым |
| B. Файловая система замечает, что Проводник открывает корень запертой папки, и показывает окно пароля | да | нет, наш код вне Проводника | пробуем вторым |
| C. Внутри запертой папки один элемент «Открыть с паролем» | да | нет | запасной, есть всегда |
| desktop.ini с CLSID и свой `IShellFolder` | да | высокий | не делаем |
| Папка превращается в файл `.wlock` | нет | нет | не делаем |
| Cloud Files API | да | низкий | расшифрованное попадает на диск, не делаем |

**Способ A.** Когда человек дважды кликает по папке, Проводник выполняет её действие по умолчанию. Обычно это «Открыть». Обработчик меню правой кнопки может предложить своё действие по умолчанию. Наш обработчик делает это только для запертых папок, а список запертых путей читает из общей памяти, без обращения к диску, за микросекунды. После правильного пароля он переводит это же окно Проводника внутрь папки. **[проверить]**: срабатывает ли подмена на Windows 10 и 11 при двойном клике в окне, в области навигации слева, в адресной строке; не ломает ли открытие обычных папок; как переводить то же окно внутрь папки.

**Способ B.** Файловая система видит каждое обращение и знает, какой процесс его сделал. Проблема: Проводник заглядывает внутрь папок не только по двойному клику, но и чтобы нарисовать миниатюру папки или понять, пустая ли она. Ещё заглядывают индексатор и антивирус. Окно пароля, которое выскакивает просто от просмотра соседней папки, раздражает сильнее, чем лишний клик. **[проверить]** через Process Monitor, можно ли отличить настоящий вход в папку от подглядывания.

**Итог P2** ([отчёт](../prototypes/p2/REPORT.md)): способ A в виде обработчика меню не работает, Проводник открывает папки по двойному клику, не спрашивая обработчики. Способ B не работает, Проводник заглядывает в корень подключённой папки и без входа. Работает новый способ **A2**: статическое действие папки в реестре (HKCU) с условием `AppliesTo`, которое подходит только запертым папкам, и списком действий по умолчанию `ZamokOpen open`. Проводник выполнил это действие при «двойном клике» на запертой папке и не выполнил на обычной. **[проверить]** вручную, что обычные папки открываются как раньше и окно не переходит внутрь запертой (`prototypes/p2/manual-p2.ps1`). Если A2 подтвердится, `zamok-shell.dll` нужен только для пунктов меню.

Если не сработает ни A2, ни остальные, остаётся C: двойной клик, внутри один большой элемент «Открыть с паролем», ещё двойной клик. Это на один клик больше, но надёжно.

## 5. Надёжность: шифрование на месте без потери данных

Главное требование (исследование 03, топ-10, п. 1). Порядок такой, что сбой на любом шаге оставляет либо нетронутый оригинал, либо полную проверенную зашифрованную копию.

1. Проверки из п. 2.1.
2. Создать `.Клиенты.zamok.tmp` и журнал операций в нём.
3. Каждый файл зашифровать во временное хранилище, сразу расшифровать обратно в памяти и сравнить отпечаток (BLAKE3) с оригиналом. В журнал записать, что файл готов. После сбоя работа продолжается с места остановки.
4. Сбросить всё на диск (`FlushFileBuffers`).
5. Переименовать временное хранилище в `.Клиенты.zamok`, а оригинал в скрытую `.Клиенты.zamok-original`. Переименование на одном диске мгновенное.
6. Подключить файловую систему на путь `D:\Работа\Клиенты` в открытом состоянии.
7. Удалить оригинал. Записать в журнал, что шифрование завершено.

После сбоя или выключения света core при старте читает журнал:
- сбой на шагах 2–4: оригинал не тронут, предлагаем продолжить или откатить (удалить временное хранилище);
- сбой между 5 и 6: подключаем папку;
- сбой на шаге 7: доудаляем оригинал.

«Расшифровать навсегда» идёт тем же порядком в обратную сторону: расшифрованная копия, проверка, переименование, удаление хранилища.

Честное предупреждение при шифровании уже существующей папки: удалённые оригиналы физически могут остаться на диске, на SSD особенно, и специальные программы их достанут. Перезапись перед удалением помогает на HDD и почти бесполезна на SSD. Защита от этого: шифрование всего диска (BitLocker или «Шифрование устройства»), программа проверяет его состояние и подсказывает (раздел 6).

### 5.1 Другие сбои

- **Программа упала, пока папка подключена.** При падении процесса WinFsp сам убирает точку подключения, путь исчезает (проверено в P1 принудительным завершением). Расшифрованное на диск не попадает. После выключения питания на пути может остаться «мёртвая» точка подключения (исследование 01, п. 1.3; проверяется в P4). При старте core находит такие точки по своему списку, снимает их и подключает заново. Пока core не запущен, на месте папки пусто: путь исчез, поэтому сторож должен перезапускать core сразу.
- **Программу удалили.** Деинсталлятор предлагает расшифровать папки или оставить их зашифрованными. Во втором случае на месте каждой папки остаётся обычная папка с файлом `КАК ОТКРЫТЬ.txt`: «откройте `.Клиенты.zamok` программой Cryptomator или zamok-recover».
- **Человек переместил или удалил папку в Проводнике.** Проверено в P4 ([отчёт](../prototypes/p4/REPORT.md)): Проводник перемещает или удаляет только точку подключения, данные в хранилище целы. Core следит за этим: новый путь узнаёт через `GetVolumePathNamesForVolumeNameW` и запоминает; если точка удалена, спрашивает, удалить ли зашифрованные данные или вернуть папку (по умолчанию вернуть). **[проверить]** перемещение на другой диск: Проводник может скопировать расшифрованное содержимое на другой диск и удалить оригиналы внутри тома, это нужно перехватывать.
- **Обновление программы.** Не ставится, пока какая-то папка открыта. Формат хранения сам не обновляется: старые папки открываются всеми новыми версиями.
- **Синхронизация.** Если папка лежит в OneDrive, Dropbox или Яндекс.Диске, облако синхронизирует скрытое хранилище, то есть шифротекст. **[проверить, P0]**: что облачные клиенты не заходят через точку подключения и не заливают в облако расшифрованное содержимое открытой папки. Если какой-то клиент заходит, папку в его каталоге не шифруем, пока не найдём решение.

## 6. Следы открытого текста в Windows

Программа сама расшифрованное на диск не пишет, но Windows и другие программы оставляют следы (исследования 01, п. 1.4, и 03, п. 3). Что делаем с каждым:

| Канал | Что делаем |
|---|---|
| Индекс поиска Windows | Все файлы отдаём с атрибутом «не индексировать», путь убираем из областей индексирования (`ISearchCrawlScopeManager`). Проверяем тестом. |
| Кэш миниатюр | Выборочно отключить нельзя. **[проверить]** варианты; минимум честно предупреждаем. |
| «Недавние файлы», «Быстрый доступ» | При запирании удаляем ярлыки из `Recent`, которые ведут в папку. |
| Автосохранение Office, временные файлы Photoshop | Пишутся в другие места. Подсказка в «Проверке следов». |
| Файл подкачки, файл гибернации | Защищает только шифрование системного диска. |
| Корзина | У виртуальной папки своей корзины нет, удалённые файлы удаляются сразу, даже при удалении с разрешением отмены (проверено в P1). Предупреждаем при первом удалении. Позже можно сделать свою корзину внутри зашифрованной папки. |

«Проверка следов» в настройках смотрит, зашифрован ли системный диск BitLocker или «Шифрованием устройства», включена ли гибернация и есть ли открытые папки в индексе поиска, и объясняет, что сделать. Если системный диск зашифрован, почти все остаточные следы при краже ноутбука закрыты.

В README модель угроз идёт первой:
- **защищает**: украденный или потерянный выключенный ноутбук; копия папки, флешка, облако; другой пользователь этого компьютера; человек, который сел за ваш компьютер, пока папка заперта;
- **не защищает**: вирус на вашем компьютере, пока папка открыта; человек, который знает пароль или PIN-код Windows Hello; удаление папки (зашифрованную папку можно удалить, её только нельзя прочитать).

## 7. Скорость

Любая зашифрованная файловая система на Windows медленнее обычного диска. На тысячах мелких файлов (git, node_modules) в 10–100 раз (исследование 02, п. 3). Для рабочих папок это главный риск удобства после двойного клика.

Что делаем с первого дня:
- **замеры в репозитории**: распаковка дерева на 70 000 файлов, `git status` и `git clone`, `npm install`, копирование файла на 1 ГБ, открытие в Проводнике папки на 10 000 файлов. Каждый замер в трёх вариантах: обычный NTFS, WinFsp без шифрования, наша программа. Так видно, сколько отнимает драйвер и сколько шифрование;
- **кэш ядра против запирания**: длинный `FileInfoTimeout` ускоряет работу, но держит сведения о файлах после запирания (P3). Поэтому при запирании кэш сбрасывается явно, а значение выбирается замером в P5;
- **кэши**: расшифрованные имена, содержимое папок, номера папок. Мы единственные, кто пишет в хранилище, поэтому кэшу можно доверять долго и сбрасывать его только своими же записями. По той же причине можно дольше держать сведения о файлах в кэше ядра WinFsp (`FileInfoTimeout`), значение подбираем замером;
- **параллельность**: многопоточная обработка запросов, шифрование кусков параллельно, аппаратный AES (AES-NI);
- **антивирус**: Defender проверяет и расшифрованные файлы через нашу папку, и шифротекст в скрытом хранилище. Проверка шифротекста бессмысленна, поэтому установщик предлагает исключить из проверки только скрытые хранилища. Расшифрованное содержимое Defender проверяет как прежде.

Замеры P5 ([отчёт](../prototypes/p5/REPORT.md)) без шифрования: большие файлы почти как на NTFS, `git status` и листинг в 2–3 раза медленнее (доли секунды), создание множества мелких файлов в 12 раз медленнее, в основном из-за накладных расходов WinFsp и двойной проверки Defender. Цели для версии 1.0 с шифрованием, по медиане трёх прогонов: большие файлы не хуже 50% от NTFS; листинг и `git status` не медленнее NTFS больше чем в 4 раза; создание мелких файлов не медленнее passthrough WinFsp больше чем в 1,5 раза. Журнал операций WinFsp всегда выключен: он замедляет работу в разы.

Если для папок с кодом формат Cryptomator окажется слишком медленным, добавляем второй формат (структура папок сохраняется, один индекс на папку), как отдельный режим «Быстрый, без мобильных приложений».

## 8. Windows 10 и 11, меню, подпись

- **Меню правой кнопки.** На Windows 10 пункты сразу в меню. На Windows 11 в первой версии они в «Показать дополнительные параметры» (или Shift+правый клик). В короткое верхнее меню Windows 11 пускает только подписанные пакеты (`IExplorerCommand` с идентичностью пакета, исследование 01, п. 3.1). Это добавим, когда будет подпись.
- **Подпись.** Без неё Smart App Control на чистой Windows 11 блокирует запуск, а SmartScreen пугает предупреждением. Azure Artifact Signing недоступен частным лицам из России. План: подать заявку в SignPath Foundation (бесплатно для открытых проектов) после первых рабочих версий; запасной вариант: платный сертификат OV.
- **WinFsp.** Лицензия GPLv3 с исключением для открытых проектов: можно класть неизменённый установщик WinFsp в свой, если наша лицензия открытая и в интерфейсе и README есть строка «WinFsp - Windows File System Proxy, Copyright (C) Bill Zissimopoulos» со ссылкой.
- **Проверка на версиях.** Windows 10 22H2, Windows 10 LTSC 2021, Windows 11 23H2, 24H2, 25H2 в виртуальных машинах, с включённой изоляцией ядра (Memory Integrity) и Defender. **[проверить]**, что драйвер WinFsp грузится при включённой Memory Integrity: по данным исследования 01, Microsoft начинает включать её автоматически.

## 9. Открытый проект и доверие

- Лицензия GPLv3: любая распространяемая изменённая версия тоже обязана быть открытой, закрытый платный клон сделать нельзя. GPLv3 подходит под исключение WinFsp.
- Сборки собирает GitHub Actions из тега, отпечатки файлов публикуются в релизе, сборка воспроизводимая: любой может собрать сам и сверить.
- Тесты шифрования на файлах, созданных настоящим Cryptomator: наша программа должна открывать его папки, а Cryptomator наши.
- Fuzzing разбора формата: на вход подаются испорченные файлы, программа не должна падать.
- Без телеметрии, без аккаунтов, без серверов.
- Публичный план независимой проверки криптоядра, когда проект подрастёт.
