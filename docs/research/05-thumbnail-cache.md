# 05. Кэш миниатюр Windows и папки Zamok

Дата: 2026-11-10. Шаг ROADMAP, этап 8: «Варианты с кэшем миниатюр, по итогам честное описание в README». Проверка на Windows 10 Enterprise LTSC 2021 (19044), без прав администратора.

## Что это

Проводник хранит уменьшенные копии картинок, видео и некоторых документов в `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db`. Кэш общий для всех папок пользователя и живёт отдельно от файлов: миниатюра остаётся, когда сам файл уже удалён или недоступен. Этим пользуются при расследованиях: картинки достают из кэша после удаления оригиналов. Старые файлы `Thumbs.db` в самих папках с Windows Vista создаются только в сетевых папках.

## Проверка

Скрипт `prototypes/thumbcache/probe-thumbcache.ps1` запускает настоящий `zamok-core` со своей папкой данных и каналом, шифрует папку с картинкой внутри `tests\tmp\thumbs` и просит миниатюру через `IThumbnailCache` (`CLSID_LocalThumbnailCache`): это тот же кэш, что у Проводника, только без окна. Для сравнения та же картинка лежит в обычной папке NTFS. Сначала `WTS_INCACHEONLY` (есть ли в кэше), потом `WTS_EXTRACT` (как делает Проводник), потом снова `WTS_INCACHEONLY`. После запирания миниатюра запрашивается по её номеру (`GetThumbnailByID`), без самого файла.

| | Атрибуты файла | До запроса | Запрос как у Проводника | После запирания |
|---|---|---|---|---|
| Обычная папка NTFS | `Archive` | нет в кэше | создана и сохранена (`WTS_CACHED`) | |
| Открытая папка Zamok | `Archive, NotContentIndexed` | нет в кэше | создана и сохранена (`WTS_CACHED`) | файла не видно, миниатюра по номеру есть (`S_OK`) |

Итог: миниатюры из папки Zamok попадают в кэш так же, как из любой другой, и остаются там после запирания. Атрибут `FILE_ATTRIBUTE_NOT_CONTENT_INDEXED`, который Zamok ставит всем файлам ради индекса поиска, на кэш миниатюр не влияет.

## Варианты

| Способ | Что даёт | Цена | Вывод |
|---|---|---|---|
| Атрибут «не индексировать» | ничего: проверено выше | | уже стоит, кэш не закрывает |
| Отключить кэш для одной папки | такой настройки в Windows нет | | невозможно |
| Политика `DisableThumbsDBOnNetworkFolders` («Отключить кэширование эскизов в скрытых файлах thumbs.db») | только файлы `Thumbs.db` в сетевых папках | к `thumbcache_*.db` отношения не имеет | не помогает |
| Политика `NoThumbnailCache` («Отключить кэширование эскизов изображений», HKCU) | по описанию Microsoft, эскизы не кэшируются | только Pro, Enterprise и Education, меняет поведение для всех папок, надёжных проверок на Windows 10 и 11 не нашлось | Zamok чужие настройки не меняет; в README не советуем, пока не проверено |
| Настройка Проводника «Всегда отображать значки, а не эскизы» (`IconsOnly` в `HKCU\...\Explorer\Advanced`) | Проводник и окна открытия файлов не делают миниатюры, значит и не кэшируют | миниатюр нет во всех папках | советуем в README и в «Проверке следов», если это важно человеку |
| «Очистка диска», пункт «Эскизы» | удаляет уже сохранённые миниатюры | вручную, Windows снова наполняет кэш при просмотре | советуем вместе с `IconsOnly` |
| Подключать том как сетевой (WinFsp с префиксом UNC) | неизвестно: кэш миниатюр работает и для сетевых папок, отдельной политики для них нет, только `DisableThumbnailsOnNetworkFolders` (показывать значки вместо эскизов) | у Cryptomator сетевой вид тома даёт другие проблемы (Windows 11 24H2 показывает его как сетевое расположение), папку на своём пути WinFsp ставит как диск; это переделка `zamok-fs` | не делаем: выгоды не видно, риск большой |
| Атрибут `FILE_ATTRIBUTE_OFFLINE` или `RECALL_ON_DATA_ACCESS` на файлах | Проводник не строит миниатюры для файлов «не на диске» | программы считают файлы облачными, Defender и резервное копирование их пропускают, «Свойства» и поиск ведут себя иначе | не делаем: ломает больше, чем закрывает |
| Атрибут `FILE_ATTRIBUTE_ENCRYPTED` (как у EFS) | не проверено | при копировании Проводник спрашивает про потерю шифрования, программы ищут ключи EFS | не делаем |

Безопасного способа на уровне файловой системы или флагов подключения нет. Всё, что действительно убирает миниатюры, меняет поведение Windows для всех папок, а такие настройки Zamok не трогает (так же решено со стрелкой ярлыка, исследование 04).

## Решение

- В README честная строка: миниатюры из открытых папок остаются в кэше после запирания, для одной папки это не отключить; кому важно, тот включает «Всегда отображать значки, а не эскизы» и чистит «Эскизы» в «Очистке диска».
- «Проверка следов» показывает, включена ли эта настройка (`IconsOnly`), и даёт тот же совет. Сама настройку не меняет.
- Если системный диск зашифрован, кэш при краже выключенного ноутбука не прочитать. От человека, который сел за компьютер, пока вы вошли в Windows, кэш не закрыт: миниатюры видны специальной программой.

## Не проверено

- Политика `NoThumbnailCache` на Windows 10 и 11: на компьютере разработки политики не меняются.
- Поведение кэша для тома WinFsp, подключённого как сетевой: потребовало бы переделки `zamok-fs`.
- Windows 11: проверка шла на Windows 10; кэш устроен так же, но отдельно не проверялся.
