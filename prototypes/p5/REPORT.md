# P5. Скорость без шифрования: отчёт

Дата: 2026-11-07. Windows 10 Enterprise LTSC 2021, SSD, Microsoft Defender включён (выключать его мы не вправе: это настройка безопасности системы). Файловая система из P3 (passthrough плюс состояние), без шифрования. Это нижняя граница накладных расходов WinFsp: шифрование добавит своё.

## Что мерили

`bench-p5.ps1`: дерево из 20 000 мелких файлов (1–8 КБ, 2000 папок, как `node_modules`) и файл 1 ГБ.

| Замер | Чем |
|---|---|
| копирование дерева внутрь | `robocopy /MT:8` |
| листинг дерева | `dir /s /b` |
| `git add` и `git commit` всего дерева | git |
| `git status` повторно | git |
| копирование файла 1 ГБ внутрь | `robocopy /J` |
| чтение файла 1 ГБ | `copy /b file nul` |
| удаление дерева | `rmdir /s /q` |

## Результаты, секунды

Основной прогон (журнал WinFsp выключен), `results.md`:

| Вариант | Копирование дерева | Листинг | git add + commit | git status | Копирование 1 ГБ | Чтение 1 ГБ | Удаление дерева |
|---|---|---|---|---|---|---|---|
| NTFS | 8,2 | 0,51 | 165 | 0,09 | 40,6 * | 0,98 | 2,2 |
| WinFsp, кэш 0 мс | 101 | 1,36 | 417 | 0,18 | 3,1 | 1,40 | 13,5 |
| WinFsp, кэш 1000 мс | 95 | 1,15 | 327 | 0,16 | 1,8 | 1,71 | 15,6 |
| WinFsp, кэш бесконечный | 142 | 1,10 | 303 | 0,16 | 2,0 | 1,43 | 13,5 |

\* Выброс: в первом прогоне тот же замер на NTFS занял 2,6 с. Похоже на проверку Defender или фоновую работу диска.

Первый прогон с включённым журналом каждой операции WinFsp лежит в `results-debuglog.md`. Журнал сам замедлял работу в разы: с кэшем 0 мс удаление дерева шло 427 с вместо 13,5, а `git add + commit` 1012 с вместо 417. В Zamok журнал WinFsp выключен всегда.

## Что видно

- **Создание множества мелких файлов в 12 раз медленнее NTFS** (8 с против 95–100 с), даже без шифрования. На каждое создание файла приходится несколько обращений из ядра в нашу программу, а Defender проверяет каждый файл дважды: через подключённую папку и в исходной папке. Это главное узкое место для папок с кодом.
- **`git add + commit` в 2–2,5 раза медленнее.** На NTFS он тоже медленный (165 с), значит, большую часть времени съедает Defender.
- **`git status` и листинг в 2–3 раза медленнее,** но в абсолютных цифрах это доли секунды: 0,16 с против 0,09 с.
- **Большие файлы почти как на NTFS:** чтение 1 ГБ за 1,4–1,7 с против 1,0 с, копирование внутрь около 2 с.
- **Кэш сведений о файлах (`FileInfoTimeout`) помогает меньше, чем ожидалось.** Без журнала разница между 0 мс и 1000 мс около 25% на git и почти ноль на остальном. Бесконечный кэш на копировании дерева даже медленнее, вероятно, из-за разброса. Значит, жертвовать безопасностью запирания ради кэша не стоит (находка P3).
- **Шум большой.** Defender и фоновая работа системы дают разброс в разы между прогонами. Для решений нужны повторы и медиана.

## Решения для Zamok

1. **`FileInfoTimeout` небольшой (порядка 1 секунды) плюс явный сброс кэша при запирании.** Бесконечный кэш ощутимого выигрыша не дал.
2. **Исключить из проверки Defender только скрытое хранилище с шифротекстом** (`.Имя.zamok`). Проверять шифротекст бессмысленно, а расшифрованные файлы Defender по-прежнему проверяет через подключённую папку. Так уйдёт двойная проверка. Нужны права администратора, установщик предлагает это с объяснением. Замерить эффект с согласия автора: включение исключения меняет настройки безопасности, ночью без спроса мы этого не делали.
3. **Честно написать в README:** для папок с десятками тысяч мелких файлов, которые часто пересоздаются (`node_modules`, кэши сборки), Zamok заметно медленнее обычной папки. Для документов, фотографий, дизайна и обычных проектов с git разница почти незаметна.
4. **Цели для версии 1.0, с шифрованием, по медиане трёх прогонов:** чтение и запись больших файлов не хуже 50% от NTFS; листинг и `git status` не медленнее NTFS больше чем в 4 раза; создание мелких файлов не медленнее passthrough WinFsp больше чем в 1,5 раза, то есть шифрование не должно заметно добавлять к накладным расходам WinFsp.
5. **Второй, быстрый формат** откладываем: узкое место сейчас в самом WinFsp и Defender, а не в формате.

## Не проверено

- Влияние исключения Defender: нужно согласие автора.
- `npm install`: требует скачивания пакетов из сети и запуска их скриптов, ночью не делали. Дерево из 20 000 мелких файлов изображает ту же нагрузку.
- Многопоточность диспетчера WinFsp и размер очереди операций: остаётся на этап 9.
