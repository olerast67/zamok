# P1. Подключение на путь папки: отчёт

Дата: 2026-11-07. Система: Windows 10 Enterprise LTSC 2021 (19044), WinFsp 2.1.25156, Rust 1.99.1, крейт `winfsp` 0.13.2. Windows 11 не проверялась: виртуальной машины пока нет.

## Что сделано

- `ntptfs/`: пример passthrough-файловой системы из [SnowflakePowered/winfsp-rs](https://github.com/SnowflakePowered/winfsp-rs) (GPLv3), без изменений в коде, только зависимость `winfsp` переведена на crates.io. Перед сборкой код проверен: нет сети, запуска процессов и реестра.
- `test-p1.ps1`: 21 проверка файловых операций через точку подключения.
- `test-p1-shell.ps1`: 6 проверок механизма копирования Проводника (`SHFileOperation`), пространства имён оболочки и сохранения в стиле Office.

Запуск: `powershell -NoProfile -ExecutionPolicy Bypass -File test-p1.ps1` (и так же второй). Сборка требует `LIBCLANG_PATH` (см. ниже).

## Что нашли попутно

- **Для сборки нужен libclang.** `winfsp-sys` генерирует привязки к заголовкам WinFsp через bindgen, а bindgen ищет `libclang.dll`. Поставлен компонент Visual Studio «C++ Clang tools» (`Microsoft.VisualStudio.Component.VC.Llvm.Clang`), путь в переменной пользователя `LIBCLANG_PATH`. В GitHub Actions на `windows-latest` LLVM обычно уже стоит, проверить при настройке сборки.
- **passthrough держит исходный файл открытым после закрытия** (кэш WinFsp, `FileInfoTimeout` = 1 с в примере). Прямое открытие исходного файла в это время даёт ошибку «файл занят». Для Zamok неважно: исходные файлы зашифрованы и пользователь к ним не ходит.
- **Word через COM в скрытом режиме завис** на невидимом окне (вероятно, окно первого запуска или входа в учётную запись Office). Это не связано с WinFsp: работа Word проверена ручным сценарием ниже и имитацией его способа сохранения.

## Не проверено

- Windows 11 и Memory Integrity: нет виртуальной машины.
- Видимость папки для другого пользователя этого компьютера: в passthrough права берутся у исходных файлов, у Zamok будет свой дескриптор безопасности. Проверим на этапе 3.
- Сохраняется ли атрибут «системный» на точке подключения между подключениями. WinFsp создаёт точку заново при каждом подключении, поэтому Zamok должен ставить атрибут после подключения или отдавать его в атрибутах корня. Проверим в P3.
- Ручные проверки ниже.

## Ручные проверки для автора (5 минут)

1. Собрать и запустить: в PowerShell `cd C:\dev\zamok\prototypes\p1\ntptfs; cargo build --release`, затем `mkdir C:\dev\zamok\tests\tmp\p1\src -Force; .\target\release\p1-ntptfs.exe -p C:\dev\zamok\tests\tmp\p1\src -m C:\dev\zamok\tests\tmp\p1\mnt`.
2. В Проводнике открыть `C:\dev\zamok\tests\tmp\p1\mnt`, перетащить туда пару файлов мышью, переименовать, удалить.
3. Создать документ Word, сохранить в эту папку, закрыть, открыть снова двойным кликом, поправить, сохранить.
4. Открыть папку в VS Code, поправить файл.
5. Правый клик по файлу в «Недавних» Word, «Открыть расположение файла».
6. Остановить программу Ctrl+C в окне PowerShell. Папка `mnt` должна исчезнуть.
