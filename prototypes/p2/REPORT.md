# P2. Двойной клик по запертой папке: отчёт

Дата: 2026-11-07, ночь. Windows 10 Enterprise LTSC 2021. Всё регистрировалось только в HKCU и убрано после проверок.

## Что проверяли

| Способ | Файлы | Как проверяли |
|---|---|---|
| A. Обработчик меню (`IContextMenu`) делает свой пункт действием по умолчанию у запертых папок | `shellext/` (DLL на Rust), `test-p2.ps1`, `test-p2-mouse.ps1` | меню через Shell API; «двойной клик» в окне Проводника через UI Automation; настоящий двойной клик мышью |
| A2. Статическое действие папки в реестре с условием `AppliesTo` и списком действий по умолчанию `ZamokP2Static open` | `test-p2-static.ps1`, `manual-p2.ps1` | «двойной клик» в окне Проводника через UI Automation |
| B. Файловая система замечает вход в папку | журнал в `prototypes/p3/gatefs` (`P3_TRACE`), `test-p2-fs.ps1` | журнал обращений к корню запертой папки в разных сценариях |

## Результаты

**A. Обработчик меню.** В меню, которое собирает Shell API, наш пункт становится первым и действием по умолчанию только у запертой папки, у обычной остаётся «Открыть». Но при «двойном клике» в окне Проводника (UI Automation) Проводник **не загрузил DLL вообще**: в журнале ни одного вызова, запертая папка открылась как обычная. Проводник открывает папки по двойному клику сам, не спрашивая обработчики меню. **Не подходит.**

**A2. Статическое действие с условием.** При «двойном клике» в окне Проводника на запертой папке Проводник **выполнил наше действие** (в журнале `invoke ...\Locked`), на обычной папке не выполнил. Это стабильно повторилось в трёх прогонах. Не удалось проверить автоматически две вещи: что окно Проводника при этом не переходит внутрь запертой папки и что обычные папки по-прежнему открываются. Проверка перехода в этом скрипте не срабатывает даже без изменений в реестре, то есть ломается сама проверка, а не подмена. **Самый перспективный способ, нужна ручная проверка** (`manual-p2.ps1`, 1 минута).

Важная деталь: если сделать действием по умолчанию только `ZamokP2Static`, у обычных папок по условию его нет, и неизвестно, вернётся ли Проводник к «Открыть». Поэтому используется список `ZamokP2Static open`: первое подходящее действие из списка.

**B. Файловая система.** Проводник открывает и читает корень подключённой папки, когда просто показывает родительскую папку, когда её обновляют и когда приходит уведомление об изменении. При входе внутрь картина похожая, только обращений больше. Надёжно отличить вход от подглядывания нельзя, окна пароля выскакивали бы сами. **Не подходит.**

Попутная находка: в асинхронных операциях WinFsp (листинг каталога) номер процесса недоступен, и вызов `FspFileSystemOperationProcessIdF` вне контекста операции роняет процесс файловой системы. Сначала нужно проверять `FspFileSystemGetOperationContext()` на null. Исправлено в `gate.rs`. Для Zamok это значит: список «кто держит файлы» строится при открытии файла, которое идёт синхронно, а не при чтении.

**Настоящий двойной клик мышью** ночью не прошёл ни на одной папке, даже на обычной: окно не получало ввод (экран выключен или рабочий стол недоступен). Это ограничение проверки, не способа.

## Как это меняет устройство Zamok

Если ручная проверка A2 пройдёт:
- `zamok-shell.dll` для двойного клика не нужен. Двойной клик ловит статическое действие в реестре, а DLL остаётся только для пунктов меню (и для верхнего меню Windows 11);
- условие `AppliesTo` не может читать общую память core. Варианты: условие по пути (core переписывает его при каждом запирании и открытии, это одна строка в HKCU) или по свойству папки, которое отдаёт сама файловая система WinFsp (например, атрибут или своё свойство в `desktop.ini`). Выбрать на этапе 5;
- команда действия запускает окно пароля `Zamok.exe --unlock "%1"`; после пароля нужно открыть папку в том же окне Проводника, это проверить отдельно.

Если не пройдёт: остаётся запасной способ C, элемент «Открыть с паролем» внутри запертой папки. Он работает всегда.

## Ручная проверка утром

```
powershell -ExecutionPolicy Bypass -File C:\dev\zamok\prototypes\p2\manual-p2.ps1 -Install
```

Дважды кликнуть `Locked`: должно появиться окно «Zamok P2», Проводник остаётся на месте. Дважды кликнуть `Normal` и любую свою папку: открываются как обычно. Проверить дерево слева и рабочий стол. Затем:

```
powershell -ExecutionPolicy Bypass -File C:\dev\zamok\prototypes\p2\manual-p2.ps1 -Uninstall
```
