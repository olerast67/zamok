# P4. Сбои и опасные действия: отчёт

Дата: 2026-11-07. Windows 10 Enterprise LTSC 2021, WinFsp 2.1, файловая система из P3 (`prototypes/p3/gatefs`).

## Что сделано

`test-p4.ps1`: 18 проверок на тестовых данных. Вспомогательный код на C# внутри скрипта умеет:
- записать точку подключения тома (`FSCTL_SET_REPARSE_POINT`, тег `IO_REPARSE_TAG_MOUNT_POINT`, цель `\Device\Volume{GUID}\`), то есть изобразить то, что остаётся после выключения питания;
- прочитать цель точки подключения;
- определить мёртвую точку: цель `\Device\Volume{...}\`, но открыть папку нельзя;
- убрать мёртвую точку: `FSCTL_DELETE_REPARSE_POINT`, затем `RemoveDirectory`.

Этот код почти без изменений переходит в `zamok-core` (восстановление при старте).

## Результаты

**18 из 18.**

| Сценарий | Что происходит |
|---|---|
| **A. Процесс файловой системы упал** при открытом окне Проводника и открытом файле | Путь исчезает сам: WinFsp убирает точку подключения. Исходные данные целы. Открытый файл дальше даёт ошибку. Окно Проводника остаётся открытым на несуществующем пути. Повторное подключение работает без всякой очистки |
| **B. Мёртвая точка подключения** (так выглядит папка после выключения питания) | Создаётся без прав администратора. Пользователь видит «путь не найден». Подключиться поверх неё нельзя. `IsStale` её находит, `RemoveStale` убирает без прав администратора, после этого подключение работает. Живую точку `IsStale` за мёртвую не принимает |
| **C. Переименование открытой папки** (`Move-Item` на том же диске) | Переименовывается только точка подключения, том продолжает работать по новому пути. После остановки WinFsp убирает и переименованную точку. Данные целы |
| **C2. Перемещение открытой папки в Проводнике** в другую папку того же диска | Проводник перемещает точку подключения (переименованием), содержимое не копирует. По новому пути видны все файлы. Данные целы |
| **D. Удаление открытой папки в Проводнике** | Удаляется только точка подключения. **Все исходные файлы целы.** Процесс файловой системы продолжает работать без пути |
| **E. Удаление запертой папки** | То же: удаляется точка подключения, данные целы |

## Что это значит для Zamok

- **Восстановление после сбоя проще, чем ожидалось.** При падении процесса WinFsp убирает точку сам, поэтому восстанавливать нужно только после выключения питания или зависания системы. Код поиска и очистки мёртвых точек готов (`IsStale`, `RemoveStale`) и не требует прав администратора.
- **Пока core не запущен, папки на месте нет**: путь просто отсутствует. Сторож должен поднимать core сразу, а установщик ставит автозапуск.
- **Удаление в Проводнике безопасно для данных**, но оставляет зашифрованное хранилище `.Имя.zamok` без папки. Core должен заметить, что точка подключения пропала, пока том жив, и спросить: «Папка “Клиенты” удалена. Удалить и зашифрованные данные или вернуть папку?». По умолчанию вернуть.
- **Перемещение в Проводнике работает само**, но core должен узнать новый путь, иначе после перезапуска подключит папку на старое место. Узнать можно у Windows: `GetVolumePathNamesForVolumeNameW` для тома WinFsp возвращает текущие пути точки подключения. Скрытое хранилище при этом остаётся на старом месте. Варианты для этапа 4: переносить хранилище следом (на том же диске это переименование) или хранить путь к хранилищу отдельно.
- **Перемещение на другой диск** не проверялось. Скорее всего, Проводник скопирует содержимое (расшифрованное!) как обычную папку и удалит оригиналы внутри тома. Это опасно: данные окажутся на другом диске открытым текстом, а из хранилища будут удалены. Проверить на этапе 4 и, если подтвердится, перехватывать: в меню «Переместить…» и предупреждение.

## Не проверено

- Настоящее выключение питания: нет виртуальной машины. Последствия изображены вручную (сценарий B), по описанию Cryptomator и WinFsp они такие же.
- Перемещение открытой папки на другой диск.
- `Remove-Item -Recurse` в Windows PowerShell 5.1 на точке подключения: известно, что старые версии PowerShell заходят внутрь ссылок и удаляют содержимое. Для Проводника это не так (сценарий D).

## Вывод

Сбои и опасные действия пользователя не приводят к потере данных. Нужны две вещи в core: очистка мёртвых точек при старте (код готов) и слежение за удалением и перемещением точки подключения.
